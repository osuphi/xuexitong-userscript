# 诊断导出说明

本项目相对上游 V3.6 新增的能力：把"出问题时到底发生了什么"整理成一份可以直接看的报告。返回 [README](../README.md)。

## 为什么需要它

上游脚本本身只有两类反馈渠道：控制台日志（页面刷新即丢失）和 60 行的面板日志区。排查"为什么卡住/为什么跳过一节/为什么找不到视频"这类问题时，这些信息往往不够，而且用户很难完整复述。诊断导出把关键状态一次性固化下来。

## 怎么用

三种方式，任选：

1. **点面板按钮**：GUI 面板上的「导出诊断」→ 下载 `xuexitong-diag-YYYYMMDD-HHMMSS.txt`
2. **控制台命令**：

   ```js
   app.exportDiagnostics();        // 可读 txt（默认）
   app.exportDiagnostics('json');  // 结构化 json
   app.getLogs();                  // 返回日志文本（可手动复制）
   app.getDiagnostics();           // 返回诊断对象（不落盘）
   ```

3. **停止脚本后仍然可用**：`app.destroy()` 之后调用 `app.exportDiagnostics()` 依然能导出已收集的内容，适合"复现完问题再收尾取证"。

## 报告里有什么

| 区块 | 内容 | 典型用途 |
| --- | --- | --- |
| 头部 | 脚本版本、生成时间、已运行时长、页面地址（去 query）、视口、可见性、jQuery 版本、UA | 判断是不是 CDN 被拦、是否在后台标签页 |
| 运行状态 | `isPlaying`、`userPaused`、`interactionBlocked`、`nextUnitPending`、`tryTimes`、视频任务点进度、**待执行定时器数量**、监控定时器是否在跑、面板折叠/位置 | `pendingTimers` 异常增长可提示定时器泄漏；`userPaused` 可解释"为什么不自动恢复" |
| 视频 | 是否找到、去 query 的地址、是否脱离文档、是否在 iframe 内、paused/ended/muted、倍率、进度、`readyState`/`networkState`、`error.code` | `readyState=0` 常是加载失败；`errorCode` 可查媒体错误类型 |
| frame 结构 | 每层 iframe 的深度、地址（去 query）、是否可访问、里面是否有 video | 定位"视频藏在跨域 iframe 里"或"iframe 还没加载完" |
| 选择器命中数 | 目录树、目录节点、高亮节点、步骤页签、下一步按钮、互动题容器、各 video 选择器、面板自身 | **页面改版排查的首选**：命中 0 的项就是失配点 |
| 课程目录解析 | `cells`/`nCells`/当前章节与节点下标/`resolveSource` | 判断是否是"找不到高亮节点"导致跳章节出错 |
| 配置 | 当前全部配置项快照 | 确认是否被手动改过（倍速、各开关） |
| LLM | 开关、密钥是否配置（**不含密钥本身**）、在途请求、本会话应答数、最近答案 | 排查自动作答不生效 |
| 未处理错误 | `window.onerror` 与 `unhandledrejection` 捕获的堆栈，最多 50 条 | 直接拿到脚本或页面抛出的真实异常 |
| 日志 | 最多 2000 条，带级别与毫秒时间戳 | 还原事件顺序（"先暂停、再恢复、再跳节"） |

## 隐私与安全

- 报告**完全在本地生成**（`Blob` + `<a download>`），不发起任何网络请求、不写 `localStorage`。
- 页面 URL 与视频 URL 都会剥掉 `?query`，只保留 `origin + pathname`，避免把播放地址里的临时票据带出去。
- 报告里**不含** API Key；只记录"密钥是否已配置"这一布尔值。
- 报告包含课程页面标题、步骤名与日志文本（其中可能有课程内容片段），分享前请自行确认。

## 配置

| 配置项 | 默认值 | 说明 |
| --- | --- | --- |
| `diagEnabled` | `true` | 是否收集日志与错误。**与 `guiEnabled` 独立**——关掉面板也会继续收集，否则出问题时没有东西可导 |
| `diagLogMaxLines` | `2000` | 日志缓冲上限，最小 50 条（超出后丢弃最旧的） |

关闭收集：`app.configs.diagEnabled = false`。只想少占内存：`app.configs.diagLogMaxLines = 200`。

## 实现要点（便于跟进上游新版本）

新增代码均以 `诊断导出补丁` 注释包裹，共三部分：

1. **采集**：`_diagInit()`（安装控制台镜像、注册 `error`/`unhandledrejection` 监听）、`_diagLog()`、`_diagRecordError()`；
2. **汇总**：`getLogs()`、`getDiagnostics()`、`_diagSelectorProbe()`、`_diagFrameSummary()`、`_diagSafeUrl()`；
3. **输出**：`_diagBuildTextReport()`、`exportDiagnostics()`、`_diagDownload()`。

同时改动了 `_guiLog()`：日志先写入诊断缓冲，再决定是否渲染到面板（原来是 `guiEnabled=false` 就直接丢弃，等于没有日志可导）。

两处遵守上游既有约定的细节：

- 延时清理走 `this._schedule()`，没有新增裸 `setTimeout`（上游对抗测试会静态扫描这一点）；
- 实现里没有 `preventDefault` / `stopPropagation`、没有 `fetch`/`XMLHttpRequest`、没有 `localStorage`。
